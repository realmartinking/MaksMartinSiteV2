# Аудит сайта и изменений — 16 сентября 2026

Объём: согласованная десктопная композиция, Branding Grid/List/Gallery/Info, Production List/Roll/Gallery/Folder, прелоадер, ввод, видео и совместимость с Safari. Проверена рабочая версия после `f135fca`; это проверка кода и живого превью, а не обещание идентичного FPS на всех компьютерах.

## Что найдено и исправлено

1. **Прыжок эмблемы в прелоадере.** Группа центрировалась целиком, но счётчик имел только минимальную ширину `3ch` и расширялся с числом/знаком процента. Теперь под него выделено постоянное место `3em`, эмблема и счётчик не сжимаются flex-контейнером. На окне 1422×800 записаны 55 значений от 0% до 100%: координата эмблемы X = 507.118 px и ширина = 143.993 px не менялись; ширина счётчика = 240 px. Вертикальное движение появления/исчезновения сохранено.
2. **Повторы List/Gallery появлялись одновременно.** Для всех циклов после первого задержка явно обнулялась. Галерея дополнительно подгружала несколько четвёрок ещё во время прелоадера. Теперь общий наблюдатель запускает появление при первом входе экземпляра в экран, а очередь сохраняет шаг 80 мс между разными порциями. После паузы следующая группа начинает новую последовательность. Ни пауза прелоадера, ни добавление четырёх повторов не сбрасывают очередь. Завершённые анимации освобождают `filter` и `transform`.
3. **Размытие при раскрытии Folder.** Внешняя плоскость и кнопка остаются с `filter: none`. Внутренний видеослой соседей плавно получает до 5 px blur, отдельный контейнер обрезает размытие по границам карточки. Выбранная карточка остаётся резкой. Закрытие тем же параметром анимации возвращает всем `none`; размеры, углы, количество видимых карт и зазор не изменены.
4. **Конфликт имени класса List.** Имя `list-item` совпадало с утилитой Tailwind для типа отображения. Проверка выявила блочное отображение вместо `inline-block`, из-за которого нарушалось центрирование. Служебный класс переименован. Для Value измерены ширина 312.622 px и X = 554.800 px на окне 1422.222 px — центр совпадает с центром окна.
5. **Одинаковые повторы раскрывались вместе.** Состояние мобильного раскрытия хранило только ID проекта. Теперь оно хранит ключ конкретного экземпляра. Одна выбранная карточка не раскрывает её повторы по всей ленте.
6. **List не имел нормального клавиатурного фокуса.** Названия стали настоящими кнопками с прежней типографикой. Фокус показывает desktop preview. Клик на desktop не создаёт скрытый мобильный видеоплеер; мобильный выбор раскрывает один экземпляр. Скрытый desktop preview на узком экране не воспроизводится. Просмотр также приостанавливается при скрытии документа.

## Дизайн и композиция

- Основной режим остаётся тёмным; шрифт — локальный Gramatika. Текст не переводился в контуры. Исходные изображения и видео не менялись.
- В Grid сохранены три колонки на проверенном десктопе, начало первого ряда около Y = 193 px, подписи 16 px / 18.75 px, исходные пропорции медиа и оптическая компоновка шапки. Измерение живого превью: Y = 192.995 px. Сверка выполнена с согласованными ранее параметрами и приложенными референсами; новый экспорт редактируемого Figma-файла в этой проверке не делался.
- Grid по-прежнему поворачивает весь ряд, а не каждую карточку независимо. Ряды имеют одну перспективу, поэтому высокая центральная карточка не пересекается с боковыми из-за разных поворотов.
- Эмблема шапки сохраняет полный видеоконтейнер и ранее проверенные границы вращения; новый фикс относится только к месту счётчика в прелоадере.
- Folder сохраняет десять видимых полос в закрытом состоянии. При выборе задние плоскости почти выпрямляются и уменьшаются за основной, передних видно три. На проверенном окне основная карточка занимает Y = 263.923…536.077 px, первая передняя начинается с 556.082 px: зазор около 20 px. Размытие внутренних слоёв не изменило эти координаты.
- Подпись Folder остаётся слева по центру, с левым выравниванием. Hover/focus показывает подпись; выбор центрирует одну карточку перед раскрытием. Произвольное раскрытие вне центра не возвращено.
- Roll сохраняет прежние размеры, наклон соседей, глубину и инерцию; остановка доводится до целого индекса. List и Gallery используют одинаковую кривую появления, длительность 1 секунда и шаг 80 мс.
- Info содержит четыре блока; переходы на него и обратно работают. AI BrandStudio и Tools остаются неактивными с Soon; Production ведёт в Folder.

## Данные, видео и нагрузка

В Branding — 18 уникальных ID. В Production — ссылки на те же четыре объекта: Value → Raif Vision Conference → Forma Houseboat → Манеры. Файлы не скопированы и не перекодированы, проекты из Branding не удалены.

Метаданные исходников Production: Value 1280×720 / 24 fps / 0.50 MiB; Raif 1920×1080 / переменная частота, контейнер сообщает около 22.39 fps / 0.55 MiB; Forma 1280×720 / 24 fps / 1.03 MiB; Манеры 1280×720 / 24 fps / 0.53 MiB. Все используют H.264 и yuv420p. Частота исходного ролика не является частотой движения карточек.

Folder держит ограниченное окно из 21 DOM-плоскости, включая невидимый запас; Roll — семь. List/Gallery добавляют элементы по мере движения. Их DOM не виртуализирован: очень долгая непрерывная сессия увеличивает память, хотя проигрывание видео ограничено областью рядом с экраном. Это существующее ограничение архитектуры, не устранённое изменением появления. Одновременное декодирование повторов всё равно требует ресурсов даже при маленьких файлах.

Общий IntersectionObserver для видео, обработка видимости страницы, кэш кадров эмблемы и оптимизация ближайших Grid-рядов сохранены. Кэш хранит исходные обработанные пиксели, без снижения разрешения. Ни внешний источник данных, ни новая библиотека анимации не добавлены. Добавленный blur работает в том же цикле раскрытия Folder; отдельного постоянно работающего таймера для него нет.

## Safari: что проверено, а что нет

На компьютере установлены Safari 26.6.2 и macOS 26.6.2 (прочитаны метаданные приложения и системы). Прямой автоматизированный доступ к Safari в этой сессии не предоставлен. Живые проверки выполнены в доступном встроенном браузере: его user agent сообщает Chrome 152.0.0.0. Эти результаты нельзя называть прогоном Safari.

По коду новые изменения используют обычные CSS filter/overflow, IntersectionObserver, MutationObserver и requestAnimationFrame. Нет зависимости от новых scroll-driven CSS animations, WebGPU или SVG-фильтров. Встроенный браузер подтвердил поддержку используемых свойств, но это не тест реализации WebKit. Существующий Tailwind v4 ориентируется на Safari 16.4 и новее: [официальные требования Tailwind](https://tailwindcss.com/docs/compatibility#browser-support).

Видео остаются muted и playsInline; для эмблемы предусмотрен fallback на requestAnimationFrame, если requestVideoFrameCallback отсутствует. Политики WebKit разрешают программное воспроизведение подходящего беззвучного видео, в том числе вне экрана: [WebKit video policies](https://webkit.org/blog/6784/new-video-policies-for-ios/). Пользовательский запрет autoplay всё равно требует отдельной проверки в браузере.

У WebKit были ошибки сочетания blur, поворота и clipping; конкретная воспроизводимая ошибка Safari 18 была подтверждена исправленной: [WebKit 296800](https://bugs.webkit.org/show_bug.cgi?id=296800). В новой реализации blur и clipping находятся внутри плоскости, а не на внешней поворачиваемой карточке. Это обоснованное разделение слоёв, но не гарантия отсутствия всех GPU-артефактов.

Lenis отдельно документирует ограничения частоты кадров Safari/энергосбережения и поведения fixed-элементов на старых Intel Mac: [ограничения Lenis](https://github.com/darkroomengineering/lenis#limitations). Поэтому одинаковую плавность Safari и Chrome без прямого теста на устройстве обещать нельзя. Новых причин требовать более свежий Safari эти изменения не добавляют.

## Проверки и оставшиеся пункты

Локальная production-сборка и проверка TypeScript завершились успешно; все 15 автоматических проверок проходят. Ошибок браузерной консоли в проверенных сценариях не обнаружено.

- Автоматические тесты: 12 проверок Folder (жесты, обратное направление, бесконечный индекс, перекрытие, зазор, число видимых полос и пять десктопных пропорций) плюс три проверки очереди появления. Проверки покрывают фактическую ошибку с порциями повторов и перенос очереди через прелоадер.
- Браузер: начальная Gallery имеет последовательность задержек 0, 0.08, …, 1.36 с на 18 видимых карточках. После скролла следующие карточки, включая индексы 24–41, получают последовательные начала, а не общий одновременный старт. List продолжает эту последовательность после первого набора из четырёх.
- Проверены выбор/закрытие Folder, отсутствие фильтра на его внешних плоскостях, возврат всех внутренних фильтров в none, переходы между разделами, геометрия Grid, шрифт и тема. На узком окне 433 CSS px один клик раскрывает ровно один экземпляр: один inline-ролик играет, все четыре desktop-preview приостановлены. Переход через desktop/mobile breakpoint сбрасывает preview. Временный диагностический компонент использовался только локально и удалён перед отправкой превью.
- Отдельный прогон Safari с трекпадом, энергетическим режимом и пользовательскими настройками autoplay остаётся непроведённым. Полный мобильный редизайн не входил в согласованный объём.
- Прелоадер остаётся анимационным счётчиком по времени, не измерителем реально загруженных байтов. Это прежнее поведение: на медленном соединении видео могут догружаться уже после него.
- В общих Open Graph метаданных найден прежний адрес `maksmartin-v2.vercel.app`. В Info ссылка Behance отличается от адреса, записанного в README. Эти контентные несоответствия отмечены для сверки перед основным релизом; адреса внешних профилей без подтверждённого актуального источника не заменялись.

Аудит не выявил удаления проектов, изменения исходных медиа или потери утверждённой логики Folder/Roll. Это не утверждение об отсутствии любых ошибок: границы проверки перечислены выше.
